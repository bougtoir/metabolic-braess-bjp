# Reviewer-critical review for *Economic Analysis and Policy* submission

**Target journal:** *Economic Analysis and Policy* (EAP, Elsevier)  
**Date:** 2026-09-05  
**Scope:** Pre-submission critical review of the gdp_tempo_paper submission package (manuscript, supporting information, figures, tables, code, data).

This review follows the internal checklist: manuscript novelty/focus/logic; statistical design; figures/tables; reproducibility; and strength of claims.

## Overall assessment

The paper addresses a measurement issue in growth accounting — the standard Solow residual confounds TFP with investment gestation lags and intangible capital — and links the correction to policy inputs (potential output, fiscal and monetary policy reactions). The method is reproducible from public Penn World Table 10.0 and World Bank WDI data, and all numbers in the generated manuscript, figures and tables are produced by the scripts in the repository. The submission now includes a broad set of robustness checks and scenario analyses. The journal fit is reasonable because EAP explicitly welcomes empirical and policy-oriented economics.

The remaining concerns below are ranked by fatalness, fix impact and feasibility.

## 1. Highest-priority concerns (address before submission if possible)

### 1.1 Submission fee and membership discount

EAP charges a **non-refundable submission fee of US$125** (US$67.50 for members of an Economic Society of Australia branch). The submitting author must be ready to pay this fee in Editorial Manager and, if claiming the discount, must obtain the discount code from the journal before submission. **Action:** include this in the submission checklist; no code change is needed.

### 1.2 Double-anonymized peer review

EAP uses **double-anonymized review**. The build script already strips the title page from `manuscript_en.docx` and produces `title_page_en.docx` separately, so the main manuscript file does not contain author metadata. The only remaining risk is the cover letter, which by definition contains author details and must be uploaded as a separate file. **Action:** verify in Editorial Manager that the manuscript upload is the anonymized version and that the title page/cover letter are uploaded in the appropriate separate fields.

## 2. High-priority concerns

### 2.1 Policy relevance in the non-technical introduction

The journal asks authors to **highlight the main insights in a non-technical introduction and conclusion**. The current introduction is technical and method-focused. A short, policy-oriented opening paragraph at the start of Section 1 would improve fit: “Official potential-output estimates feed directly into fiscal rules and monetary-policy responses. We show that, once investment gestation lags and intangible capital are accounted for, conventional TFP growth estimates are revised by up to several percentage points in episodes such as ... .” The exact numbers can be taken from Table 7.

### 2.2 Figures and tables as separate files

The EAP author guidelines state that **figures should generally be uploaded as separate files and not embedded in the manuscript text file** when the submission system requests separate figure files. The current package embeds figures inline in `manuscript_en.docx` and `supporting_information_en.docx`, but also provides the `figures_en.pptx` and separate `Figure_*.png` / `Supplementary_Figure_*.png` files. **Suggested fix:** mention in the cover letter or reviewer note that high-resolution separate figure files are provided; prepare TIFF/EPS versions only if requested by the editor. The current PNG files are publication-ready at 300 dpi resolution generated by `matplotlib`.

### 2.3 Highlights character count

Highlights must be **3 to 5 bullet points, each a maximum of 85 characters**. The current `highlights_en.md` should be verified against this limit. The build script does not enforce the 85-character limit, so a manual check is needed before submission.

## 3. Medium-priority concerns

### 3.1 Synthetic scenarios must remain clearly labeled

The new future scenarios (M4_AI_surge, M4_fiscal_stimulus, M4_TFP_level_only) and the γ_price sensitivity are **counterfactual/synthetic**. This is correctly stated in Section S.17 (“These are not economic forecasts...”), and the main text Section 6.4 already uses cautious language. A single sentence in S.17 emphasizing that the AI and fiscal-stimulus paths are “stylized projections” rather than forecasts would further protect against misreading.

### 3.2 Monte Carlo sample-length assumptions

The Monte Carlo calibrations (United States, Republic of Korea, France, Colombia) cover a useful range. However, the sample lengths (T = 30, 40, 50) are smaller than the full OECD historical sample for the United States. Justifying why T = 50 is the relevant upper bound for many countries would strengthen the method section. **Suggested fix:** add one sentence noting that many country series are 40–55 years long, so T = 50 is empirically relevant.

### 3.3 Clustering choice

The cluster analysis uses k-means with k = 3 and reports silhouette scores and bootstrap stability in Table 10b. This is a good start. A reviewer may ask why k-means rather than a mixture model or hierarchical clustering. The SI now documents the silhouette and stability criteria; adding one sentence in S.18 that the partition was also qualitatively inspected for interpretability would deflect this concern.

## 4. Low-priority / optional concerns

### 4.1 JEL codes

The JEL codes currently include E01, E22, E52, E62 and O47. This is appropriate for EAP, but adding **E44 (Financial Markets and the Macroeconomy)** could strengthen the financial-crisis episodes.

### 4.2 References

Verify that all references are in Vancouver/numbered order, that no orphan citations exist, and that any AI-assisted drafting is disclosed if required by Elsevier’s generative-AI policy. The current `audit_submission.py` does not check references; a manual grep of the reference list against in-text citations is recommended.

### 4.3 Line numbers / double spacing

Elsevier journals increasingly require **line numbers** in the review manuscript. The current `manuscript_en.docx` does not include line numbers. The submission system often generates these automatically, but if the journal asks for a Word file with line numbers, they can be added in Microsoft Word before upload.
